# P3.3: Task affinity

Goal:
Steps 2..n of a run go to the pod that served its first step: run-id -> pod with a TTL, cleared when the run ends. The first
step is still picked by load and prefix (the default scorers).

Depends on:
P3.2

Files allowed:
gateway/runrouter/, config/real.yaml, config/real-plain.yaml, config/sim.yaml, config/demo.yaml (routing.run_ttl_seconds),
infra/routing-values.sh, infra/helm/ (the extra port), infra/manifests/agent.yaml (PICKER_URL),
agent/agent_runtime/ (the end-of-run call, config), agent/tests/, loadgen/load_generator/replay.py,
loadgen/load_generator/experiment.py, loadgen/tests/, experiments/affinity.yaml (new), experiments/log.md, experiments/results/,
experiments/graphs/, PLAN.md (P3.3 row), docs/task-cards/38-P3.3-task-affinity.md

Interfaces / outputs:
- Filter: with routing.affinity and a pin on a pod among the candidates, returns only that pod; otherwise every candidate.
- PreRequest: records run-id -> the chosen pod and renews its TTL.
- POST /runs/{id}/end on the picker's extra port, 204 whether or not the pin existed. Sent by the agent runtime after its
  final save and by the replayer as a run stops, only when routing.plugin is on. A failure is logged and left to the TTL
  (httpx.HTTPError only): a run's answer must not depend on it.
- routing.run_ttl_seconds: a first guess of 300, longer than the longest call (agent.llm_timeout_seconds 120) plus its gap.
- A JSON log line per decision with run-id, step, pod and reason (first, pinned).
- experiments/affinity.yaml: profile real, the converted trace, pattern baseline, seed 6, variants default, affinity.

Notes:
Tests first, table-driven with a fake clock: first step unpinned; later steps pinned; TTL expiry unpins; TTL renews on use;
end of run removes the pin; another run is untouched; a request with no x-run-id passes through. The map is in memory in one
picker pod, so a picker restart forgets pins and runs fall back to load + prefix, a stated limitation.
From earlier tasks: report stalls and the queue and KV split, not only hit rate (P2.5); a capacity effect over the KV limit can
read as a cache effect (P2.4); on a replay, a pinned step's cached_tokens should be at least the previous prompt less 24
(P2.4); on 2 pods the default picker moved 28-43 later steps on real and 10 on sim, so sim understates moves (P2.9).
