# P2.10a: App backend: SQLite schema, register, login, logout

Goal:
app/ holds a FastAPI service on SQLite (sqlite3, stdlib) with the D7 schema (users, sessions, chats, messages,
attachments) and register / login / logout with a session cookie. Proven by pytest; nothing runs in the cluster yet.

Depends on:
gate-1 (independent of the other Phase 2 tasks)

Files allowed:
app/ (new uv workspace member: pyproject.toml, app package, tests), pyproject.toml (workspace member, pytest
pythonpath, mypy_path), uv.lock, config/real.yaml, config/sim.yaml, config/demo.yaml (an app section),
versions.md (the component column), docs/task-cards/33-P2.10a-app-auth.md

Interfaces / outputs:
- Schema: users (id, email unique, password hash, created), sessions (token hash, user, expires), chats (user, title,
  created), messages (chat, role, text, run_id, created), attachments (message, file id, name, type, bytes). Applied
  at startup; the version is stored (PRAGMA user_version) so P3.12 can add columns.
- POST /auth/register, POST /auth/login (sets an HttpOnly, SameSite=Strict session cookie), POST /auth/logout,
  GET /auth/me. Passwords with hashlib.scrypt and a random salt per user; only a hash of the session token is stored,
  so a copy of the database holds no usable session.
- Config: app.session_ttl_seconds, app.scrypt (n, r, p), app.min_password_length, each with a comment saying why.
- Logs: JSON, request-id on every line (D12; these lines are outside a run).
- Dependencies: fastapi, uvicorn at the agent's pins; no new package (no passlib, no ORM).

Notes:
Tests first: register -> login -> GET /auth/me passes; wrong password -> 401; expired session (fake clock) -> 401;
logout ends the session; duplicate email -> 409; the stored password is not the password and two users with the same
password get different hashes. Comparison of hashes with hmac.compare_digest. One writer (D7), so no connection pool.
