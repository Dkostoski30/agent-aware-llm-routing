# P2.1a-1: Contracts tools and text documents in the run request

Goal:
The agent has the contracts scenario's three tools (read_document, extract_clauses, diff_clauses), deterministic,
with enum arguments (D10). A run request can carry plain-text documents next to CSV files; the tools take them by
file ID (D13). Several tool calls in one reply (e.g. read_document on two contracts) run as one step.

Depends on:
gate-1, P1.7 (closed)

Files allowed:
agent/agent_runtime/ (a new documents module, tools.py, loop.py, app.py where files are read), agent/tests/ (new
document tests; fixtures under agent/tests/fixtures/), schemas/run-request.v1.json, schemas/examples/run-request.v1.*,
schemas/tests/test_schemas.py (new cases only), config/real.yaml, config/sim.yaml, config/demo.yaml (new agent keys,
the contracts clause of system_prompt), docs/task-cards/20-P2.1a-1-contracts-tools.md

Interfaces / outputs:
- run-request.v1 files[] gains optional "type": "csv" | "text", default "csv" so every request valid today stays
  valid. Additive; the agent is the only reader of the schema until P3.12.
- Text document format: UTF-8 text; a line "## <title>" starts a section, the text up to the next heading is the
  section's body. A contract's sections are its clauses. A document with no heading is rejected with 422.
- read_document(file): the document's name and its section list (title, word count); never the whole text (D13:
  files never enter the context, only tool results do).
- extract_clauses(file, clause): the body of one section. clause is an enum of the section titles of the run's text
  documents, normalised (lower case, numbering dropped) so "4. Termination" in one contract and "Termination" in the
  other are the same value. A clause the file lacks is a tool error, not an invalid call (D10).
- diff_clauses(left, right, clause): the clause in two documents, compared word by word (difflib, stdlib), as a list
  of changed passages "before -> after", capped. left/right are enums of the text file IDs; left == right is a tool
  error.
- Tools are offered by file type until P4.8 adds the scenario step (D13): text files -> read_document,
  extract_clauses; two or more text files -> also diff_clauses. CSV files keep the CSV tools.
- New config keys (all profiles, comment saying why each value): agent.max_clause_chars (bounds one clause body in
  the context), agent.max_diff_changes (bounds a diff result). agent.max_file_bytes / max_files apply to text files too.
- system_prompt gains the contracts clause, the same text in every profile.

Notes:
Tests first, table-driven, on two fixture contracts that differ in two clauses: section parsing (headings, empty
body, no heading -> FileError), each tool's result for known inputs, the clause enum across both files, a clause
missing in one file -> tool error, diff on identical clauses -> no changes, caps applied, a reply with two
read_document calls -> both results in one step and one on_step callback. The tool calls of one reply already run in
order as one step (P1.3a-1); they are in-process Python, so running them concurrently would change nothing measurable
and is not done. "Reads documents in parallel" means the model asks for both in one reply; the parallel LLM calls of
P3.6 come from the replayer's fan-out (P2.3). Whether the 1.7B actually sends both calls in one reply is not
guaranteed; the done-when shows it once, P4.7 measures scenario quality after P4.8.
The tools, tool list and prompt change, so the P1.7 adapter is stale from here (P2.1b retrains). The demo go/no-go
rerun waits for P2.1a-3, which changes the CSV runs' tool list too.
