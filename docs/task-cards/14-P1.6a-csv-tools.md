# P1.6a: CSV tools and files in the run request

Goal:
The agent has the three CSV-analysis tools of the demo (csv_summary, group_by, compare), deterministic, with enum
arguments (D10). A run request can carry CSV files, which the tools take by file ID (D13). This moves the CSV part of
P2.1 forward so the P1.6 go/no-go tests the demo's real tools.

Depends on:
P1.3b

Files allowed:
agent/ (tools module, file handling, tests), schemas/run-request.v1.json (add optional files),
schemas/examples/run-request.v1.valid.json, schemas/examples/run-request.v1.invalid.json,
schemas/tests/test_schemas.py (new cases only), config/real.yaml, config/sim.yaml, config/demo.yaml (agent keys
below), docs/task-cards/14-P1.6a-csv-tools.md

Interfaces / outputs:
- run-request.v1 gains optional files: [{"id": slug, "name": string, "content": UTF-8 CSV text}]. Additive and
  optional; no component other than the agent reads the schema yet.
- Files are kept with the run in Redis, under the run's key prefix and TTL, so P4.4 failover finds them too. A file
  over agent.max_file_bytes, or more than agent.max_files, rejects the request with 422.
- The tool schemas are built per run: the file argument is an enum of the run's file IDs, column arguments are enums
  of the columns in those files. That is what makes a wrong argument detectable (D10, auto) or impossible
  (D10, required).
- csv_summary(file): row count, columns with their type (number or text), min / max / mean of each number column.
- group_by(file, by, value, agg enum sum|mean|count|min|max): one row per group, sorted by the aggregate.
- compare(file, by, value, agg, left, right): the aggregate for two groups, their difference and percent change.
  left and right are free strings checked against the column's values, because an enum per column can't be
  expressed in one schema. The exact signature is settled in plan mode.
- Tool results are capped at agent.max_result_rows rows so they fit the 4096-token context (D13: files never enter
  the context, only tool results do).
- Until P4.8 adds the scenario step (D13), a run sees every registered tool: calculator plus the three CSV tools.
- New config keys (all profiles, each with a comment saying why): agent.max_file_bytes, agent.max_files,
  agent.max_result_rows.

Notes:
Tests first, table-driven, on fixture CSVs: each tool's output for known inputs; a column outside the enum is rejected
in auto mode with the allowed values in the message; a file over the limit -> 422; the per-run schemas list exactly
the run's file IDs and columns; a text column passed as a value column is a tool error, not a crash. Python's csv
module only, no pandas (no new dependency).
