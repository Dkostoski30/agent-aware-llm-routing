# P5.1a: spike on compiled real pods, measuring only

Added 2026-11-24, the first card of Phase 5, on branch `feature/phase-5` (off `084f67a`, Gate 4).

Goal:
Before two nights of routing squares (P5.1b, P5.1c), find out whether P3.7's load still overloads the real pods, now
that they run CUDA graphs (P4.13b, 16x faster per token). The same run also measures how far apart two runs of one
picker land, whether upstream's `session-affinity-filter` loads and holds runs, and how long one variant takes.

Depends on:
Gate 4 (`084f67a`). P3.7's load (`experiments/routing-burst.yaml`) and its overload criterion (card 42).

Phase 5 decisions (the user, 2026-11-24; they bind the later cards, not this one's run):
1. **Branch** `feature/phase-5`, merged and tagged `gate-5`. The system stays at Gate 4: a bug fix is its own commit,
   and every file run before it runs again.
2. **P5.2's real 1<->2 runs again on compiled pods.** P4.5's four files stay in the log as the eager result.
3. **Real comparisons are Williams squares of four files, each file a different seed.** The seeds are 6 plus the
   next three that meet P2.4's rule for the pattern. Runs are paired within a file.
4. **E1 is two real squares:** headline (round-robin, default, session-affinity, plugin), then ablation (plugin, and
   the plugin without the overload guard, without parallel spill, and without priority).
5. **E1's plugin is affinity, overload guard, parallel spill and priority.** Warm-up routing belongs to E2.

Files allowed:
- `experiments/p5-1a-spike.yaml`: real, the converted trace, `burst-fan-out`, seed 6, `pod_stall_seconds: 30`. Three
  variants, in this order: `default`, `default-again` (the same picker under another name), `session-affinity`.
- `infra/helm/router-session-affinity-values.yaml`: the default picker's scorers and weights with upstream's filter in
  front (`strategy: session_id`, source `x-run-id`, a 300 s binding like `routing.run_ttl_seconds`), plus
  `--allow-experimental-plugins`, because the filter is registered at Alpha stability.
- `loadgen/tests/test_experiment.py`: three tests. They hold the spike's load to `routing-burst.yaml`'s, the two
  default variants to each other, and the filter to the run header, the pin's TTL and the default's weights.
- This card, PLAN.md's Phase 5 rows, and the `experiments/log.md` entry.

What gets measured (fixed before the run):
| # | Measure | Rule |
|---|---|---|
| 1 | Overload | P3.7's: after at least 2 of the 4 bursts (120/240/360/480 s), a pod has more than 1 call waiting within 60 s, read from `vllm:num_requests_waiting` in Prometheus as card 42's spike did. The run ends in a shutdown, so the series is saved to a file first; the vLLM logs `make experiment` keeps (`Waiting: N reqs` every 10 s) are the fallback. Read on each default variant. **If it fails on either, no square runs on this load.** The options for a heavier one come back to the user; nothing is tuned in this card. |
| 2 | Noise | Total run time of `default-again` against `default`, in %. The squares cannot resolve an effect smaller than this. Reported, not judged. |
| 3 | Upstream filter | It loads if the variant runs: the picker refuses an Alpha plugin without the flag, and a bad config, at start, which fails the rollout. It holds runs if later steps stay on their run's previous pod (from the CSV), and its hit rate is reported beside default's. |
| 4 | Budget | Minutes per variant, from the restart to the replay's end, from the meta. This sets how long nights 2-4 really are. |

Done when:
`make experiment NAME=p5-1a-spike` finishes all three variants with no stall, and the four numbers go into
`experiments/log.md` whatever they show. Whether the squares run follows from criterion 1 alone.

If the session-affinity variant fails to start, the spike stops there and reports it. No fix goes in under this card
(rule 8).

Run (the user, laptop idle, Windows' AC standby off):
```
make test
make lint
make down
make up
make experiment NAME=p5-1a-spike
```

Result (2026-11-24, hash e9337329fa9e; full numbers in `experiments/log.md`):
- Overload met by its letter at 2 of 4 bursts in both default runs, at most 3 waiting per pod (eager: 5-12).
- Noise: `default-again` 11.6% under `default` in total run time.
- The filter loaded and held every run (0 of 287 later steps moved), hit rate 0.851 against 0.766-0.788; its -13.1%
  is inside the noise, and generation sped up 36% through the variants' order.
- 8.2 min per replay, 11.7 min per variant, 38 min in all.

Decided after the result (the user, 2026-11-24): at this load the overload guard and parallel spill would barely act,
so P5.1's squares run a heavier burst (10 runs per burst instead of 5), checked first by one default replay against a
stricter rule: more than 1 call waiting on a pod within 60 s after every burst (P5.1a-2).

## P5.1a-2: the heavier load, checked before the squares (approved 2026-11-24)

Files allowed:
- `config/real.yaml`, `real-plain.yaml`, `sim.yaml`, `demo.yaml`: a pattern `burst-fan-out-heavy` beside
  `burst-fan-out`, which stays as it is. It keeps the base rate (0.02 runs/s), the 120 s period and the fan-out (half
  of later steps as 2 calls), with 10 runs per burst and 50 in all: 4 bursts x 10, plus the ~10 that arrive at the base
  rate in the 480 s they span. The same in every profile.
- `experiments/p5-1a-heavy.yaml`: one `default` variant, the spike's file except for the pattern.
- `loadgen/tests/test_replay_plan.py`: the pattern differs from `burst-fan-out` in those two numbers only, in every
  profile; at seed 6 it starts 4 runs before the first burst, then 10, 10, 10 and 8 at 120/240/360/480 s.
- `loadgen/tests/test_experiment.py`: the file runs the spike's load except for its pattern, and drops the runs before
  the first burst.

Rule, fixed before the run: **more than 1 call waiting on a pod within 60 s after every one of the 4 bursts**, read as in
P5.1a. Also reported: failed calls, and calls that hit the 120 s deadline, since twice the burst could tip the pods into
timeouts. If the rule fails, the result goes back to the user and no third load is tried here (rule 8).

Done when: `make experiment NAME=p5-1a-heavy` finishes with no stall, and the rule's reading goes into
`experiments/log.md` whatever it shows.

Result of P5.1a-2 (2026-11-24, hash c80f9d4fdf07; full numbers in `experiments/log.md`): the rule met at all 4 bursts,
5-7 calls waiting per pod; 573 calls, 0 failed, no stall, longest call 14.2 s. The replayer started 40 calls more than
50 ms late (at most 1,698 ms, 11.4 s in all, 0.9% of the run time); P5.0's comparison reports it per variant (Claude's
proposal, decided with card 73). P5.1's squares run `burst-fan-out-heavy`.
