# P3.1: The picker built from source, unchanged

Read 2026-11-09 from the pinned source (llm-d-router v0.11.0, commit a5cbe60; chart digest in `infra/router-chart.sh`), nothing built yet:
- `cmd/epp/main.go` is three lines around `runner.NewRunner().Run(ctx)`, and `go.mod` has no `replace` directive, so a module of ours can require v0.11.0 and call the same runner. No fork and no vendored copy.
- Plugins register in a package-level table (`fwkplugin.Register(type, stability, factory)`), so ours are added from our own `main` before `Run` (P3.2). Alpha plugins need `--allow-experimental-plugins`; ours are not registered as Alpha.
- Upstream's image: `golang:1.26.8` build stage, `gcr.io/distroless/static:nonroot` runtime, `CGO_ENABLED=0`. Its `go.mod` asks for Go 1.26.6; versions.md's local Go is 1.27.2, which runs the tests.
- The chart builds the image name as `router.epp.image.registry/repository:tag` and takes `pullPolicy`, so a local image needs values only.

Found while planning (2026-11-10): Helm's `--set` overrides every `--values` file, so a tag passed that way would put the upstream variants on our image and the check would compare our image with itself; the tag goes in a values file before the variant's. `set-routing.sh` only reads the tag and never builds, since it must not ask for sudo mid-experiment; after a change to `gateway/`, `make picker-image` comes first. The node's image list can't tell whether k3s has the image without sudo: the kubelet reports at most 50, largest first, and the node holds 41. `values: null` in an experiment file now means the self-built picker, also in `baseline*.yaml`, whose results refuse a rerun while they exist.

Decided 2026-11-09 with the user: this check runs on sim, not real: it makes no latency claim and sim has no GPU noise. PLAN.md's "exactly like upstream" can't be literal, since two runs of the same picker differ, so upstream runs twice and those two runs give the yardstick.
