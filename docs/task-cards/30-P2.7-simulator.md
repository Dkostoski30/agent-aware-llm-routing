# P2.7: Simulated pods (llm-d-inference-sim) as the pool's backend

Goal:
make up PROFILE=sim deploys llm-d-inference-sim pods instead of vLLM, selected by the same InferencePool, so the
replayer runs against simulated pods through the same gateway and picker. No GPU, so the pod count can go past 2.

Depends on:
P2.3 (the replayer); P2.8 can run before or after (it uses the real profile)

Files allowed:
infra/charts/sim/ (new chart), Makefile (up, sim-deploy), config/sim.yaml (a simulator section), versions.md (the
simulator image by digest), loadgen/load_generator/replay.py and loadgen/tests/test_replay.py (the pod's name),
infra/checks/test_sim_chart.py (new), experiments/log.md, docs/task-cards/30-P2.7-simulator.md

Decided (2026-11-05, after reading v1.0.0's source and running its image once in Docker):
- Image v1.0.0, digest sha256:1908c421...; v1.1.0 was 2 days old.
- A new chart, not a switch in the vllm chart (the user's choice), named and labelled like it: Deployment and Service
  vllm, release vllm, label app.kubernetes.io/name=vllm. The InferencePool, make experiment's restart, make replay's
  /tokenize and make down work unchanged; moving between profiles needs make down first. Service, PodMonitor and
  dashboard are copies; a test fails if the dashboard's two copies differ.
- kv_cache_blocks 1024, not the real 274: a full cache makes the simulator answer HTTP 500 (pkg/kvcache/block_cache.go),
  where real vLLM makes the call wait, and 61.5% of the converted trace's prompts are over 2,000 tokens. 1024 is
  max_num_seqs x 256 blocks; a test fails if it gets too small. Stated limitation: 3.7x the real cache, so hit rates
  can read high; P2.9 measures it.
- The replayer takes the pod from the x-inference-pod header when a reply has no system_fingerprint.
- Cold start is --startup-duration, with the readiness probe on /health/ready; /health is 200 at once.
- --zmq-endpoint= turns off KV-cache events, which the picker's estimating prefix scorer does not read.
- No render sidecar: the docs ask for one with the KV cache, but the built-in tokenizer's cache works (Docker run:
  cached_tokens 0 then 96 on a 105-token prompt). A chat template there adds 5 tokens against the real 12; make replay
  measures it, so prompts keep the trace's lengths.
- A prompt over max_model_len gets a 400. Prompt + max_tokens over it gets a shorter reply, which the replayer fails.

Interfaces / outputs:
- The simulator image pinned by digest (versions.md), the newest release at least two weeks old.
- Pods carry the vllm chart's pod labels, so the InferencePool and the PodMonitor select them unchanged, and expose
  the vllm:* metrics the EPP scorers and P1.1's dashboard read (checked in plan mode against the pinned version).
- config/sim.yaml simulator section: time to first token, time per output token, KV-cache size, prefix-cache
  behaviour (cached vs uncached prefill, D4), cold start (D4), max concurrency. Until P2.8 each value is the measured
  P0/P1 number it comes from, with that comment; P2.8 replaces them with the calibration table's.
- Cold start: if the simulator has no startup delay of its own, the pod becomes Ready only after the configured cold
  start (e.g. a readiness gate on a delay); how is settled in plan mode.
- make up PROFILE=sim skips the GPU, model download and vLLM steps; the agent is not deployed on sim (nothing to
  answer tool calls), so make smoke is not expected to pass there.

Notes:
The simulator must accept the replayer's requests: streaming chat completions, max_tokens, ignore_eos (P2.3), and the
D1 headers through the gateway. Check what it does with a prompt longer than its configured context. Memory: two
monitoring pods, the gateway and N sim pods in the 10 GB VM (P1.2 measured the fixed part); record each sim pod's
memory.

Done when (I run this myself):
make test, make lint                            -> pass
make down && make up PROFILE=sim                -> sim pods Ready, no vLLM pods
make replay TRACE=<P2.2b trace> PATTERN=steady PROFILE=sim OUT=<new file>
                                                -> every call answered; the access log shows sim pods' endpoints;
                                                   Grafana shows the sim pods' queue and KV-cache panels; the replay's
                                                   lines have cached_tokens above 0 and the sim pods' names

Record in:
experiments/log.md, versions.md
