# P1.6b: Practical go/no-go on the demo model

Goal:
One command runs 5 CSV questions x 2 seeds on the 1.7B demo model, once in each D10 mode, scores every run
automatically and prints the result. Afterwards the go/no-go is known and config/demo.yaml keeps the better mode.

Depends on:
P1.6a

Files allowed:
experiments/demo-go-no-go.yaml (new), experiments/data/ (new: the fixture CSV), experiments/go_no_go.py (new),
experiments/tests/ (new: scorer tests), experiments/results/ (new: the result CSV), Makefile (new target go-no-go),
pyproject.toml (pytest paths), config/demo.yaml (agent.tool_choice after the result, agent.answer_tolerance),
experiments/log.md, docs/task-cards/15-P1.6b-demo-go-no-go.md

Interfaces / outputs:
- experiments/demo-go-no-go.yaml (D11): the CSV file, the 5 questions, the expected tools per question, seeds [1, 2],
  modes [required, auto]. The question wording lives here; the answers do not.
- go_no_go.py: for each mode, sets agent.tool_choice for the run, then sends 10 runs through the agent (5 questions
  x 2 seeds) with the CSV attached. The expected answer of each question is computed in the script with the
  statistics module, independently of the agent's tools, so a tool bug can't hide by agreeing with itself.
- A run is correct when its final answer contains the expected number within agent.answer_tolerance and every
  expected tool was called. Failed runs count as wrong.
- Output: one row per run (mode, question, seed, correct, steps, invalid calls, duration) in
  experiments/results/demo-go-no-go-<yaml hash>.csv (D11), then per mode "N/10 correct" and auto's invalid-call
  count.
- Switching mode: the script restarts the agent with the other value, through the ConfigMap, not a code path.
- Decision: go if at least one mode reaches 9/10. config/demo.yaml keeps that mode (required on a tie, since it
  can't produce a malformed call). Below 9/10 in both: narrow the tasks, or ask about a FINKI GPU server at
  Checkpoint 1 (PLAN.md P1.6).

Notes:
Tests first for the scorer: a number inside and outside the tolerance, a number written with a thousands comma, a
missing expected tool, a failed run. The 5 questions are different kinds (summary, group total, group mean, two-group
compare, a two-step question), so one easy question can't carry the score. Needs make up PROFILE=demo: one 1.7B
replica (D8).

Done when (I run this myself):
make down && make up PROFILE=demo  -> exit 0, one vllm pod Running
make test                          -> scorer tests pass
make go-no-go                      -> 20 rows; "required: N/10 correct", "auto: N/10 correct, K invalid calls";
                                      the result CSV exists

Record in:
experiments/log.md (both scores, invalid-call count, the decision, the mode demo.yaml keeps)
