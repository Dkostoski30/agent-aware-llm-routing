# P2.1a-2: Support tools on an orders CSV and a policies document

Goal:
The agent has the support scenario's three tools (get_order, get_policy, draft_reply), deterministic (D10). The
data comes from the run's files (decided 2026-11-01 with the user): an orders CSV and a policies text document in the
P2.1a-1 format.

Depends on:
P2.1a-1

Files allowed:
agent/agent_runtime/ (a new support module, tools.py), agent/tests/ (new support tests; fixtures under

Interfaces / outputs:
- Orders CSV: a CSV file with an order_id column (fixture: order_id, customer, item, status, ordered_on,
  delivered_on, amount). Policies: a text document whose sections are policy topics (Returns, Refunds, Shipping, ...).
- get_order(file, order_id): the order's row. file is an enum of the run's CSV files that have an order_id column.
  order_id is a string checked against the file, like compare's left/right (P1.6a): an enum of every ID would put
  the whole column into the tool schema, which every call carries in the 4096-token context. An unknown ID is a tool
  error with no list of IDs.
- get_policy(file, topic): the body of one policy section; topic is an enum of the section titles (the P2.1a-1
  normalisation).
- draft_reply(orders, order_id, policies, topic): a reply to the customer built by Python from the order row and the
  policy section, so every date and amount in it is the data's. What it computes (e.g. a return deadline from a
  "<n> days" rule in the section) is settled in plan mode; free-text generation by the model is not part of it.
- Offered by file type until P4.8 (D13): get_order with a CSV that has an order_id column, get_policy with a text
  file, draft_reply with both.
