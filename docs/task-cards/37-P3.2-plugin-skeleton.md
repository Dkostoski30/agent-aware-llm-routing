# P3.2: Plugin skeleton, flags from the profile

Decided 2026-11-09 while planning Phase 3: the plugin is a **filter**, not a scorer as PLAN.md's first wording had it. A scorer's weight can be outvoted by the queue and KV scorers, so "pinned" would only mean "usually". A filter that returns only the pinned pod is a hard rule, and returning every pod hands the choice back to the default scorers, which is what "first step picked by load + prefix" asks for. Upstream splits it the same way (`session-affinity-filter`).

`routing.plugin` is a master switch, off in every profile until Phase 4's demo needs it. With it off the picker runs the chart's `default-plugins.yaml`, so Gate 2's experiment files stay valid (their `epp_config` names that file).
