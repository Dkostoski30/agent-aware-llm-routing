# P4.5: the four autoscalers on real pods at 1<->2

Planned 2026-11-20. D5: the simulator extends the autoscalers to scale, and real vLLM at 1<->2 is the ground truth. Since P4.12
the comparison has four variants, not three: cpu (P3.10), queue (P3.10), remaining (P3.9b), pressure (P4.12).

What the simulator ranked (P3.10, one seed per pair, four pairs): remaining work and the queue finish within noise; remaining
work scales in the same scrape or earlier (30 s earlier on burst-fan-out), and asks for fewer pods (4-7 against 8), at
31-56% fewer idle pod-minutes. CPU and pressure do not run on the simulator (D5; P4.12, no KV admission there).

# P4.5: real-hardware validation of the autoscalers

Goal:
Four experiment files run the four autoscalers on real pods at 1<->2 on one replay, in a balanced set of orders, and
make autoscale-compare reads their results into one table and the verdict fixed below, before any run.

Depends on:
P3.10, P4.3 (drain), P4.4 (retry), P4.12

Files allowed:
experiments/autoscale-real-1to2-a.yaml, -b.yaml, -c.yaml, -d.yaml (new), loadgen/load_generator/autoscale_compare.py (new),
loadgen/tests/test_autoscale_compare.py (new), loadgen/tests/ (a test holding the four files to their orders), Makefile
(autoscale-compare), experiments/log.md, experiments/results/, PLAN.md (P4.5 row; one sentence in P5.2's row),
docs/task-cards/61-P4.5-real-autoscaling.md

Interfaces / outputs:
- The four files: profile real, the converted trace, pattern burst, seed 6, runs_discarded 4, the warm-up and
  pod_stall_seconds 30 of experiments/autoscale-real.yaml, the default picker (D2), each variant at min_replicas. They differ
  only in the order of their variants. With A cpu, B pressure, C queue, D remaining (alphabetical):
    a: A B D C   cpu, pressure, remaining, queue
    b: B C A D   pressure, queue, cpu, remaining
    c: C D B A   queue, remaining, pressure, cpu       (a reversed)
    d: D A C B   remaining, cpu, queue, pressure       (b reversed)
  A balanced Latin square (Williams): each variant once in each position, each variant right after every other once, so a
  drift over a sitting or what one variant leaves for the next falls on every variant alike. a/c and b/d are reverse pairs,
  so PLAN's rule for real-pod comparisons (both orders, repeated) holds.
- make autoscale-compare META="<a.meta.json> <b.meta.json> ..." reads only the .meta.json files make experiment wrote
  (autoscale.crossings, autoscale.scale_up_windows, autoscale_summary, failed_calls) and refuses files of differing replays
  (trace, pattern, seed, profile_sha256) or with a variant missing. It prints, per variant per file, and per variant as
  mean and min-max over the files: when the remaining work, the queue and the context crossed their targets, when spec
  replicas rose, when the second pod was Ready, finished and failed kept runs, run completion p50 (finished runs), makespan,
  idle pod-minutes, KEDA restarts; then the mean per position (1st..4th) over all variants, to show order drift; then the
  verdict. It writes the per-file table to experiments/results/autoscale-real-1to2-compare.csv, the same twice.

Verdict (fixed before the runs; the user, 2026-11-20: judge only what can exist at 1<->2):
  "same ranking as on the simulator" when all three hold for remaining against queue:
  1. scale-up: remaining's mean spec-rise time over the files is no later than queue's;
  2. completion: the difference of their mean run completion p50s is within the larger of the two variants' own min-max
     spreads across the files (each variant's spread is what a rerun of the same autoscaler moves);
  3. failures: remaining's failed kept runs, summed over the files, are no more than queue's.
  Otherwise "different", and the log entry explains which line failed and why. A file in which a variant was scaled before
  its replay has no spec-rise time for it; the count of such files is printed and the mean is over the rest.
  Idle pod-minutes are reported, not judged: at a ceiling of 2 no autoscaler can ask for fewer than 2 pods, so the
  simulator's lead (fewer pods) cannot show, and whichever scales earlier pays more idle time. CPU and pressure are placed
  by the same numbers, not judged.

Notes:

  context crosses on the warm-up runs alone (~60 s), but the HPA's 10% tolerance held pressure to 100 s; remaining work
  at 60-125 s; the queue last. The second pod is Ready ~145-165 s after the rise. Pressure's run lost 10 of 26 kept runs
  to the 120 s deadline when Ready came after the second burst (240 s), CPU's 1: the deadline turns lateness into failures,
  which is why line 3 is in the verdict and completion p50 is read beside the finished-run count.
- Stated, not changed: warm-up routing and priority off (the default picker); retry (P4.4) and drain (P4.3) on as in the
  profile; no scale-down within the ~600 s replay (stabilization 300 s), so interrupted runs stay with P5.2.
- A variant refused by the stall check stops its file; that file is rerun whole, same hash. Results of a file whose
  run was not idle (laptop in use, Windows asleep) are moved aside, as autoscale-real-laptop-in-use/, and rerun.
- P5.2 reuses these 16 runs as its real 1<->2 data (the user, 2026-11-20); P5.2 adds the simulator at scale and a replay
  with a scale-down.
- Time: ~15-17 min per variant (pod reset to 1, warm-up, ~600 s replay), 16 runs ~4.5 h. Two sittings, one reverse pair
  each: a + c, then b + d.
- Tests first: the four files' orders (Williams square, otherwise identical to autoscale-real.yaml's replay), the
  refusals (mixed replays, a missing variant), the verdict's three lines on known numbers incl. a variant scaled before

## Decided while planning (2026-11-20)

The user:
- Four autoscalers in one sitting-pair design; the earlier sketch of 3 rotated files no longer balances with 4 variants,
  so 4 files in a Williams square.
- The verdict judges only what can exist at 1<->2: scale-up time, completion within spread, failed runs; idle pod-minutes
  reported with the ceiling explanation.
- P5.2 reuses these runs as its real 1<->2 data.

Claude's choices:
- The letters are alphabetical; any assignment is as balanced.
- The compare reads .meta.json only, since make experiment already stores the crossings, windows and summary there.
- The verdict's spread is min-max, not a standard deviation: 4 samples per variant.
