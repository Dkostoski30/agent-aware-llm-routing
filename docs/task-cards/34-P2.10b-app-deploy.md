# P2.10b: App backend in k3s, data kept across make down

Goal:
make up runs the app backend as one replica (D7) with its SQLite file on persistent storage: data survives a pod
restart and make down && make up; make reset-app wipes it.

Depends on:
P2.10a

Files allowed:
app/Dockerfile, infra/manifests/app.yaml (Deployment, Service, volume), infra/deploy-app.sh, infra/down.sh (only to

docs/task-cards/34-P2.10b-app-deploy.md

- One replica, strategy Recreate (two pods must never write one SQLite file, D7).
- Storage that make down does not delete: a hostPath directory outside the k3s data (e.g. ~/.local/share/thesis/app)
  or a PVC whose volume survives the uninstall; which one is settled in plan mode by what infra/down.sh removes.
- make reset-app: deletes the database file (and restarts the pod), the only way data is removed.
- GET /healthz for the readiness probe.

agent: P3.12 connects them.
