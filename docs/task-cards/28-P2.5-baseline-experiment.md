# P2.5: First baseline experiment: round-robin vs default picker

Goal:
make experiment NAME=baseline regenerates, from scratch, a CSV and a graph comparing round-robin routing with the
default Endpoint Picker on the same replay. It is the experiment framework every later experiment (P3.7, P3.10,
P5.x) uses: one YAML file, results stamped with its hash (D11).

Depends on:
P2.4

Step 1 · Spike (max 1 hour)
How round-robin is served through the same gateway. Candidates: agentgateway's own load balancing on an HTTPRoute
straight to the vllm Service (bypasses the EPP), or an EPP scheduling profile with a round-robin or random picker in
the pinned llm-d-router v0.11.0. Report which exists, and what each changes besides the picker, before the plan.

Spike result (2026-11-03, read-only, from source at the pinned tags llm-d-router v0.11.0 and agentgateway v1.6.0):
- llm-d-router has max-score-picker, random-picker and weighted-random-picker, and no round-robin picker. With no scorers
  every score ties and max-score rotates the tied endpoints by a per-request counter. The list it rotates comes from
  ranging over a Go map (pkg/epp/scheduling/scheduler_profile.go, runPickerPlugin), so its order is not stable: a
  standalone copy of those steps on Go 1.27.2 with 2 pods gave 50/50 picks and switched pod on 78% of picks (strict
  round-robin 100%, random 50%). The image's Go version can differ, so make experiment reports the live share.
- An HTTPRoute straight to the vllm Service gives agentgateway's power-of-two-choices on a health score
  (crates/agentgateway/src/types/loadbalancer.rs, select_p2c): load-aware, not round-robin, and it skips the EPP.
- vLLM's /reset_prefix_cache exists only with VLLM_SERVER_DEV_MODE=1.

Decided 2026-11-03 with the user:
- The round-robin variant is max-score-picker with no scorers, on the same gateway and EPP path as the default. The log
  calls it near round-robin and gives the live share of picks that switch pod. A strict one needs the plugin of P3.
- The vLLM pods restart before each variant, since both send identical prompts at one seed and the second would find the
  first's text cached. The EPP restarts too, which empties its prefix index. No chart change.
- 40 runs at 0.02 runs/s, seed 6, on the AgentProcessBench trace: the rate P2.4 measured, and the first 20 runs are P2.4's
  replay. The first 5 runs are discarded, and they still count as load on what overlaps them.
- Each pod gets warm-up calls straight to its IP before the replay, since a first call on a new pod takes 26-29 s (P2.4)
  and discarded runs need not reach both pods. They skip the gateway, so the picker does not learn them.
- Clock jumps are counted per variant, printed and kept in the .meta.json, and refuse nothing. So are the largest gap
  deviation (P2.4's open point, reported instead of checked), the switch share and the calls per pod.
- A failed call stops only its run and is a result: its row has blank times, and the run counts as failed, not as a time.
- Calls are reported over and under the KV limit apart (P2.4). tokens_on_pod is an upper estimate: a call's own prompt and
  reply tokens plus those of every call on its pod that overlaps it up to its first token.
- experiments/baseline-check.yaml: 5 runs of the recorded trace on the same runner, about 15 min, to try the whole path
  before the long run. config/ and experiments/graphs/ join the files allowed.

Decided 2026-11-03 with the user, after the first baseline run (hash 2069d38644d6, laptop in use during its default
variant): its default variant generated 15% slower and its warm-up calls, which skip the picker, were 15% slower, while
default always ran second, so routing, order and the host could not be told apart.
- That run's results stay as the "before", in experiments/results/first-baseline-laptop-in-use/.
- baseline.yaml runs again, as the done-when says, followed at once by experiments/baseline-reversed.yaml with the variants
  the other way round and the laptop idle: round-robin, default, default, round-robin, which cancels a steady drift.
- make experiment's report gives generation speed and warm-up time per variant, so this shows without a one-off script.
- The first run was on Armoury Crate's Turbo plan with sleep and screen-off on AC at 10 min, against versions.md's
  Performance and never, and had a 10 s Modern Standby at 14:50:51 in its round-robin variant. The remaining runs use
  Performance with both set to never. Read back after the runs, that plan has the ID versions.md already names, so
  versions.md stays: Armoury Crate lists Turbo or Performance in that place, depending on the mode.

Files allowed:
experiments/baseline.yaml (new), experiments/baseline-check.yaml (new), experiments/baseline-reversed.yaml (new), loadgen/ (experiment runner, CSV and graph
modules, tests), Makefile (experiment, experiment-graph, experiment-compare), infra/ (only the routing variant the spike picks),
config/ (the baseline pattern, report.yaml), pyproject.toml / loadgen/pyproject.toml, uv.lock (matplotlib), versions.md, PLAN.md
(the P2.5 row), experiments/log.md, experiments/results/, experiments/graphs/,
docs/task-cards/28-P2.5-baseline-experiment.md

Interfaces / outputs:
- experiments/baseline.yaml: trace, pattern, seed, variants [round-robin, default], profile, warm-up runs to discard,
  warm-up calls per pod, KV capacity per pod.
- make experiment NAME=baseline: for each variant, restart the pods, switch routing, warm each pod, replay, collect the
  replay trace as experiments/results/baseline-<hash>-<variant>.jsonl; then experiments/results/baseline-<hash>.csv (one
  row per call: variant, run, task_type, step, pod, ttft_ms, duration_ms, gap_before_ms, prompt_tokens,
  completion_tokens, cached_tokens, moved, tokens_on_pod, over_kv_limit), baseline-<hash>.meta.json and
  experiments/graphs/baseline-<hash>.png (run completion time, prefix-cache hit rate, and time to first token over and
  under the KV limit, per variant). The default picker is put back when it ends, also after a failure, or the run says it could not.
- make experiment-graph CSV=<csv>: the graph again, from the CSV alone.
- make experiment-compare CSVS="<a.csv> <b.csv>" STALL_SECONDS=<n> (decided 2026-11-03 with the user, rule 9): sums, paired
  runs, the average across files, the same variant between files, and slow first tokens, from the CSVs alone.
- config/report.yaml (decided 2026-11-03 with the user, rule 6): the settings of the reports and the graph's layout, apart
  from the profiles, since a result is stamped with its profile's hash and a report's setting changes no measurement.
- matplotlib (decided 2026-11-01 with the user): in loadgen only, never in the agent image, pinned in versions.md
  (the newest release at least two weeks old).
