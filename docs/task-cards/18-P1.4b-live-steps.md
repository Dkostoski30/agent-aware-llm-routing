# P1.4b-1: Run events over SSE

Goal:
The agent streams a run's steps over SSE (D6): GET /runs/{run_id}/events replays the steps saved in Redis, sends
each new step as it is saved, then one final event with the status and the answer. The UI half is P1.4b-2 (card 18b).

Depends on:
P1.4a

Files allowed:
agent/ (SSE endpoint, config field, tests), config/real.yaml, config/sim.yaml, config/demo.yaml (events poll
interval), schemas/run-events.v1.json, schemas/examples/run-events.v1.{valid,invalid}.json,
schemas/tests/test_schemas.py, docs/task-cards/18-P1.4b-live-steps.md, docs/task-cards/18b-P1.4b-2-step-cards.md

Interfaces / outputs:
- GET /runs/{run_id}/events: text/event-stream, 404 for an unknown run. Events, named by the SSE event field, data
  JSON:
  run   run_id, task, expected_steps, created_ms (once, first)
  step  run_id, step, expected_steps, content, tool_calls [{name, arguments, result}], error (one per step)
  end   run_id, status, answer, error, steps, invalid_calls, elapsed_ms (once, last; then the stream closes)
- New steps reach the endpoint by polling Redis every agent.events_poll_seconds, so the replay and the live steps
  come from the same place (Redis), and a client that reconnects mid-run gets every step again. No SSE id field,
  so a reconnect never resumes halfway.
- schemas/run-events.v1.json describes the three events (D12); the agent tests validate every event they get.

Notes:
Decided 2026-10-28 with the user: P1.4b split in two (size); polling Redis over an in-process queue or a Redis
stream (one code path, works with any number of agent replicas); the events get their own schema. FastAPI's own SSE
support (fastapi.sse, in the pinned 0.143.0) sends the events and keep-alive pings; no new dependency.
invalid_calls is only on end: from the saved messages an invalid call's error and a tool's data error look the same.
Known limit: a run whose background task stopped without a final save stays running in Redis, so its stream polls
until the history TTL. That happens when the agent pod dies (P4.4) and when execute in app.py raises (a Redis error
while saving a step, a tool raising an unexpected error), which P1.3a-2 left uncaught; not changed here.
Review 2026-10-28 (after commit 90f34a3): schema text for a null result, the poll comment, two test checks (the SSE
event name matches its data; arguments that are not JSON reach the stream as text), this limit, and D12's list of
schemas fixed in a follow-up commit.

Done when (I run this myself):

RUN=$(curl -s -X POST localhost:8080/runs -H 'content-type: application/json' -d '{"task":"What is 7 times 8?"}' | jq -r .run_id)
curl -N localhost:8080/runs/$RUN/events  -> event: run, then each event: step as it happens, then event: end with
                                            an answer containing 56; curl exits
same curl again                          -> the whole run replayed at once; curl exits
