# P1.4a: Angular shell in the design system

Goal:
ui/ holds an Angular app in the Tenax design system (D14): tokens, dark and light themes, top bar and the New task
screen. Submitting a task starts a run on the agent and opens the run route that P1.4b fills.

Depends on:
P1.3b (POST /runs through make agent-forward)

Files allowed:
ui/ (new, from ng new), Makefile (new target ui), .pre-commit-config.yaml (only if the eslint / tsc hooks need a path
fix), versions.md, docs/task-cards/17-P1.4a-ui-shell.md

Interfaces / outputs:
- Tokens from docs/design-system/tokens.json as CSS custom properties; dark is the default, light switches from the
  top bar (README: Visual foundations). The choice is remembered per browser.
- Components ported from docs/design-system/components with the same inputs and the same ag- classes: TopBar,
  Composer, ScenarioCard, NewTaskScreen. The previews are the reference.
- Scenario cards only fill the composer with an example task (D14); they don't pick the scenario.
- Submit posts run-request.v1 to /api/runs and navigates to /runs/:id.
- make ui: ng serve on localhost:4200; its proxy sends /api to localhost:8080 (make agent-forward).
- No cluster panel yet (P3.11); the layout leaves its column for it.

Notes:
Strict TypeScript and eslint, as the pre-commit hooks already expect. Fonts as the design system loads them. Unit tests
first for behavior: a scenario card fills the composer; submit is disabled on an empty task; submit sends the
run-request body and navigates to the returned run_id; the theme toggle switches and remembers. Dependencies: only what
ng new 22.2.2 (Angular CLI pinned in versions.md) generates, listed in the plan; no UI library.
