# P2.11: Infra fixes after P2.1b

Goal:
make smoke passes when vLLM pods left Failed by a reboot or make down + up are still listed; make vllm-deploy refuses a
model.lora whose name or path names other weights than its sha256; the heldout comment gives P2.1b's run count; lint
leaves result files as the scripts wrote them.

Depends on:
P2.1b

Files allowed:
infra/checks/smoke.sh, Makefile (vllm-deploy recipe, heldout comment), .pre-commit-config.yaml, config/real.yaml
(model.lora comments only), PLAN.md (P2.11 row, Order line), experiments/log.md,
docs/task-cards/23b-P2.11-infra-fixes.md

Interfaces / outputs:
- smoke.sh, prometheus check: the vLLM pods that must have a vllm:num_requests_running sample are the ones in phase
  Running (not being deleted, as now). The pods check above it already requires every desired pod of the Deployment
  Ready. Pods in another phase are named on the ok line ("not Running, skipped: [...]"), only when there are any.
- make vllm-deploy, when model.lora is set, before the weights' sha256 check: model.lora.name must end with the first
  12 hex digits of model.lora.sha256, and model.lora.path too (a trailing / ignored). Otherwise one line, e.g.
  "vllm-deploy: model.lora.name thesis-b03ea3894e7c does not end with 5554fcf81b09, the start of model.lora.sha256",
  and exit 1 before anything is pulled or deployed. Profiles without model.lora are not checked, as now.
- Makefile heldout comment: 336 runs, ~90 min (P2.1b: 92 and 86 min of run time).
- .pre-commit-config.yaml: trailing-whitespace and end-of-file-fixer exclude ^experiments/results/, with a comment.
  The trailing space lint removed from the P2.1b baseline CSV stays removed (that commit's CSV is what P2.1b compared).
- config/real.yaml: the model.lora name and path comments say make vllm-deploy refuses a mismatch.

Notes:
Failed pods: the kubelet starts vLLM before the NVIDIA device plugin is back, rejects the GPU request
(UnexpectedAdmissionError), and the ReplicaSet never deletes the Failed pod; kubectl shows STATUS Unknown. Until now
the fix was kubectl delete pod -l app.kubernetes.io/name=vllm --field-selector=status.phase=Failed. The slip
vllm-deploy now refuses: P2.1b's config/real.yaml first had the new model.lora.name with the old path and sha256, so
vLLM served the old weights under the new name. The test pod below is a bare pod: the ReplicaSet's selector also
has pod-template-hash, so the ReplicaSet does not adopt it.

Done when (I run this myself):
make lint, make test                          -> pass
cp config/real.yaml config/slip.yaml
yq -i '.model.lora.name = "thesis-b03ea3894e7c"' config/slip.yaml
make vllm-deploy PROFILE=slip                 -> the name line, make exits non-zero, no helm output
yq -i '.model.lora.name = "thesis-5554fcf81b09" | .model.lora.path = "~/.cache/thesis/finetune/adapters/b03ea3894e7c"' config/slip.yaml
make vllm-deploy PROFILE=slip                 -> the path line, make exits non-zero, no helm output
rm config/slip.yaml
make vllm-deploy PROFILE=real                 -> deploys as before (both vLLM pods listed Running)
kubectl run smoke-failed-pod --restart=Never --labels=app.kubernetes.io/name=vllm --image="$(yq -e .image infra/charts/vllm/values.yaml)" --command -- false
kubectl wait pod/smoke-failed-pod --for=jsonpath='{.status.phase}'=Failed --timeout=60s  -> condition met
make smoke                                    -> exits 0; the ok prometheus line names smoke-failed-pod as skipped
kubectl delete pod smoke-failed-pod
