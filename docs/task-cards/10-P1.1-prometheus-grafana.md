# P1.1: Prometheus + Grafana scraping vLLM

Goal:
Prometheus scrapes every vLLM pod and a Grafana dashboard shows queue length, KV-cache usage and prefix-cache hit
rate per pod.

Depends on:
P1.0

Files allowed:
infra/install-monitoring.sh (new), infra/helm/monitoring-values.yaml (new),
infra/charts/vllm/templates/podmonitor.yaml (new), infra/charts/vllm/templates/dashboard.yaml (new),
infra/charts/vllm/dashboards/vllm.json (new), config/real.yaml, config/sim.yaml, config/demo.yaml,
Makefile (up, grafana, vllm-deploy comment), infra/down.sh, versions.md,
docs/task-cards/10-P1.1-prometheus-grafana.md

Interfaces / outputs:
- kube-prometheus-stack 92.3.0, release monitoring in namespace monitoring. Off: Alertmanager, default rules,
  node-exporter, default dashboards, k3s-internal scrape targets (etcd, scheduler, controller manager, kube-proxy).
- config key monitoring.scrape_interval_seconds (all profiles) -> prometheusSpec.scrapeInterval.
- The vllm chart owns its PodMonitor (one scrape per pod, label pod) and its dashboard ConfigMap
  (grafana_dashboard=1, uid thesis-vllm, title "vLLM pods").
- Panels (vLLM v0.31.0 metric names, read from vllm/v1/metrics/loggers.py in the image):
  queue = sum by (pod) (vllm:num_requests_waiting)
  KV-cache usage = max by (pod) (vllm:kv_cache_usage_perc)
  prefix-cache hit rate = rate(vllm:prefix_cache_hits_total) / rate(vllm:prefix_cache_queries_total), per pod
- make up installs monitoring before vllm-deploy (the PodMonitor needs its CRD); make down uninstalls it.
- make grafana: port-forward to http://localhost:3000, anonymous Viewer access.

Notes:
Rate windows use $__rate_interval, which Grafana derives from the datasource's timeInterval; the chart sets that to
the scrape interval, so no window is hardcoded. No logic beyond configuration, so no unit tests.

Done when (I run this myself):
make up                      -> exit 0, both vllm pods 1/1 Running
kubectl get pods -n monitoring -> prometheus, grafana, operator, kube-state-metrics Running
make grafana, open http://localhost:3000/d/thesis-vllm
make service-check (second terminal)
  -> the dashboard shows one line per vllm pod in all three panels; the hit-rate panel has points only for the
     minute the requests ran (a rate with no queries is 0/0, drawn as a gap)

Record in:
versions.md (kube-prometheus-stack), experiments/log.md
