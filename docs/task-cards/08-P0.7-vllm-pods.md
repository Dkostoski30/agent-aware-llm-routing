# P0.7: Two vLLM pods behind a Service

Goal:
Two vLLM pods run in k3s on the shared GPU and answer through one Service.

Depends on:
P0.6, P0.4

Files allowed:
infra/charts/vllm/** (small local Helm chart), infra/helm/device-plugin-values.yaml (time-slicing),
infra/checks/service_check.sh, Makefile (targets vllm-deploy, service-check), versions.md

Interfaces / outputs:
- infra/charts/vllm: Deployment + Service + values. Values come from config/<profile>.yaml (replicas, model, gpu_memory_utilization, max_model_len, tool_call_parser).
  Pods: runtimeClassName nvidia, HF cache mounted from the host (hostPath to ~/.cache/huggingface, read-only),
  readinessProbe on /health with initialDelaySeconds long enough for model load (from config, comment why), same vLLM flags as vllm-run.sh.
  GPU access: if the device plugin path worked in P0.6, time-slicing with 2 slots (device-plugin-values.yaml) and limits nvidia.com/gpu: 1 per pod;
  if ladder step 3 worked, no GPU request, env NVIDIA_VISIBLE_DEVICES=all. The path is a chart value, not a code change.
- make vllm-deploy PROFILE=real: helm upgrade --install with values rendered from the profile.
- infra/checks/service_check.sh: port-forwards the Service, sends the chat_check.sh requests through it, prints which pod answered (from pod logs). Exit 1 on failure.

Notes:
Stop the P0.4 Docker containers first, the GPU can't hold both setups.

Done when (I run this myself):
make vllm-deploy PROFILE=real
kubectl get pods -> both vllm pods Running and Ready
make service-check -> answer + tool_calls through the Service, exit 0
