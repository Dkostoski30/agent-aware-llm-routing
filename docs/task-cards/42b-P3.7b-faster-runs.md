139 s of B lies in A's runs. With "less than half" for B, B holds 435.4 s. 259 and 241 of the plugin's 287 later calls stayed

Claude's choices, stated in the plan and approved ('start'):
- **The pin is set in Filter when the rule leaves one pod.** A burst sends 5 runs at once (`replay.patterns.burst-fan-out`);
  first calls that did not see each other would all go to the one light pod. The count and the pin share the pins' lock, so
  each first call counts the ones placed before it. When several pods are level, the scorers choose and PreRequest pins as
  before: first calls that arrive together then see the same counts, as they would on the default picker (a stated limit).
  A pin set in Filter for a call that then gets no pod stays until the end of run or the TTL; the retry goes to that pod,
  the lightest anyway.
- **Pins carry the run's remaining work** as of its latest call, `max(expected - step, 1)` from `x-step` and
  `x-expected-steps` (D2's count): a spill or a parallel spill moves the step on too. A header that is missing or no whole
  number counts 1, the floor.
- **Only a run's first call**, one with no live pin. A run whose pod left the pool goes to the scorers, as since P3.4.
- **least_work_slack 2**, profile-only like the other thresholds, a first guess with its comment in the profiles.
- **`least_work_first` with affinity off is refused** in `infra/routing-values.sh` and `experiment.py`, as the guard is, and
  is inert in the plugin: without affinity no pins are kept.
- **The faster verdict gives no verdict when a run did not finish** in either variant of any file: a failed run has no time,
  and leaving it out could leave out the slowest (P3.7's first session).
- **Both files keep `not_worse_tolerance: 0.05`**, so a rule that bought run time with first tokens shows.
