# P2.8: Calibrate the simulator on the real 0.6B

Goal:
A calibration table measured on real vLLM pods: TTFT and time per output token vs concurrency, cached vs uncached
prefill, cold start time (D4). config/sim.yaml's simulator section is set from it.

sim/ (calibration script, tests, calibration table and its notes), Makefile (calibrate), experiments/calibrate.yaml
(new: concurrency levels, prompt and reply lengths, repetitions, seed), config/sim.yaml (simulator section),
experiments/log.md, docs/task-cards/31-P2.8-calibration.md. Added 2026-11-05 with the user: pyproject.toml (sim on
pytest's pythonpath and mypy_path), config/real-plain.yaml (new), PLAN.md and CLAUDE.md (D11 names real-plain),
loadgen/load_generator/replay.py and loadgen/tests/test_replay.py (P2.8a-2: _stream_reply made public, a rename only).

Split (2026-11-05):
- P2.8a-1: experiments/calibrate.yaml, sim/calibrator/config.py, prompts.py and stats.py with their tests,
  config/real-plain.yaml and its test, pyproject.toml, D11. No cluster.
- P2.8a-2: the live driver (port-forward, kubectl, streaming, resume) with fake-cluster tests, make calibrate, the
  overnight run, the log entry.
- P2.8b: config/sim.yaml from the table, after the questions below marked "after the numbers".

Decided (2026-11-05, the user's answers before the plan):
- The plain model is a committed profile, config/real-plain.yaml: real.yaml without model.lora, held equal to it by
  sim/tests/test_real_plain_profile.py. D11 amended.
- One file per model and pod count, sim/calibration-<hash>-{lora,plain}-{1pod,2pods}.csv (one row per pod and cell),
  and sim/cold-start-<hash>-{lora,plain}.csv (one row per pod that started).
- Grid: concurrency 1, 2, 4, 8; prompts 256, 1024, 2048, 3584 tokens; replies 64 (ignore_eos); cache modes uncached,
  full (the same prompt sent just before) and partial (its first 75% sent just before); 20 calls per cell, the full
  grid for both models and both pod counts, about 8-9 h overnight.
- A cell keeps c calls in flight with c streams that send back to back until 20 are done; a row counts the calls that
  ended with fewer in flight.
- Calls go to one pod through kubectl port-forward, not the picker. 2 pods: both get the same cell at once.
- Warm-up after every pod start until a call's TTFT is under warmup.settled_ttft_ms, at most warmup.max_calls, or the
  run stops; the first call's TTFT goes to the cold-start file.
- Cold start: 5 starts of one pod beside a running one, 3 of both at once, per model, from Kubernetes' timestamps.
- Clock: Windows' clock against the monotonic one at the start and end of each file, drift in the meta, not
  corrected; clock jumps counted per cell.
- make calibrate refuses to start unless Windows' plan is Performance and AC sleep and hibernate are never.
- A rerun skips finished files and redoes missing or .partial ones; a finished file of another length is refused.
- Built in P2.8a-2: each file has its own .meta.json (profile sha256, Windows' clock drift over the file, warm-up
  times), so a rerun never rewrites another file's meta. A prompt's length is checked on every call from the reply's
  prompt_tokens, and the chat template's tokens once per file with /tokenize. Every reply must name the pod it was
  sent to.
- After the numbers (P2.8b): adapter or plain for config/sim.yaml; time_factor_under_load and max_num_seqs; the first
  slow call, waiting on KV tokens and GPU sharing, which the simulator cannot express; whether p95s feed its std-devs.

Interfaces / outputs:
- make calibrate: streaming calls straight to one pod (not through the picker, so the pod is known), at each
  concurrency level and prompt length from the experiment file; uncached = a fresh prefix per call, cached = the
  same prefix sent before. Writes sim/calibration-<hash>.csv: concurrency, prompt_tokens, cached, ttft_ms p50/p95,
  per-token ms p50/p95.
- Cold start: pod created to Ready, and Ready to first answered call, from Kubernetes timestamps, over several pod
  restarts (P0.3/P0.4 measured 114-160 s in Docker).
- With and without the LoRA adapter (decided 2026-11-01: model.lora stays in config/real.yaml until this card
  measures both and picks the profile to calibrate on). P1.7 saw runs ~2x slower with --enable-lora.
- Both pods share one GPU: measure one pod alone (the other scaled to 0) and both loaded at once, since D5 validates
  at 1 and 2 pods and the simulator has to model what one pod sees in each case.
