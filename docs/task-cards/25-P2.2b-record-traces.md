# P2.2b: Record runs as trace.v1 JSONL

Decided 2026-11-02 with the user, before the code; the card below is updated to match:
- The trace is named like go_no_go's results, <experiment>-<hash>-<agent image tag>[-<adapter>].jsonl, not
  <experiment-hash>.jsonl: P4.8 re-records with a changed agent, possibly from the same experiment file, and must not
  replace the trace earlier replays used. A recording refuses to start if its file exists (a re-run wrote over a night's
  held-out CSV on 2026-10-29). Nothing is written until the last run has ended, so a stopped recording leaves no partial
  trace.
- The recorder reaches Redis with kubectl exec deployment/redis -- redis-cli GET and the agent at its Ready pod's IP, as
  infra/checks/smoke.sh and go_no_go.py do. So no port-forwards to start and stop, and no redis-py in loadgen. kubectl and
  the Ready-pod lookup are copied from go_no_go.py, not imported, so loadgen does not depend on experiments/.
- Runs that fail from the model's output (agent.max_steps, agent.max_invalid_calls, a cut-off reply) stay in the trace:
  real agents make that traffic too. A call that got no reply (5xx, timeout, 4xx) stops the recording, since the trace
  would miss that call. A trace line does not say its run failed: this trace has no failed runs, and P2.4 decides how a
  later recording's are told apart when it derives expected-steps (decided after the review; no sidecar file or schema
  field now).

The package is loadgen/load_generator, as agent/ holds agent_runtime: pytest's importlib mode registers the directory
loadgen/ as the module loadgen for a test under it, which hides an inner package of that name.

Settled here, from card 24's report: a call without prompt or completion tokens, an empty pod or a negative count fails
trace.v1, so it stops the recording. vLLM's default fingerprint vllm-0.31.0-<hash8> would still pass as a pod name; the
real chart always sets the pod's name, so it stays reported for the simulator (P2.7). The experiment's hash covers its
YAML file only, as in go_no_go.py, not the files it attaches, and the trace's name does not cover config/real.yaml, also
as in go_no_go.py.
