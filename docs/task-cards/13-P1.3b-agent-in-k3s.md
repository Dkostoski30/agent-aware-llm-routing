# P1.3b: Agent runtime and Redis in k3s, a real task through the gateway

Goal:
make up builds the agent image, imports it into k3s and runs it next to Redis. A real calculator task completes
through the gateway, its headers show in the gateway log, and its history is readable from Redis.

Depends on:
P1.3a

Files allowed:
agent/Dockerfile (new), agent/.dockerignore (new), infra/deploy-agent.sh (new), infra/manifests/redis.yaml (new),
infra/manifests/agent.yaml (new), infra/checks/agent_check.sh (new), Makefile (up, new targets agent-deploy,
agent-check, agent-forward), infra/down.sh, versions.md, experiments/log.md,
docs/task-cards/13-P1.3b-agent-in-k3s.md

Interfaces / outputs:
- Redis: one Deployment + Service, official redis image pinned by digest, no persistence (run history is
  short-lived, D7).
- Agent: one Deployment + Service on port 8080. config/<PROFILE>.yaml is mounted as a ConfigMap; the gateway and
  Redis addresses come from environment variables. imagePullPolicy Never; the tag is a hash of agent/, so a code
  change always rolls out a new pod.
- infra/deploy-agent.sh PROFILE: docker build -> docker save | k3s ctr import (the image is ~150 MB, far from the
  9 GB vLLM import that crashed k3s in P0.7) -> kubectl apply -> rollout status with a named timeout.
- make agent-forward: port-forward of the agent to localhost:8080 until Ctrl+C (P1.4 proxies to it).
- make agent-check: sends "What is 7 times 8 plus 3?" with a fixed seed, polls until done (timeout is a named
  constant), prints the answer, the gateway access-log lines with that x-run-id, and the run's keys from Redis.
  Exits 1 if any of the three is missing.
- make up runs, in order: k3s, monitoring, model, vllm, gateway, redis, agent; infra/down.sh in reverse.

Notes:
The Python base image is pinned by digest. No logic, so no unit tests; the loop's logic was tested in P1.3a. The
check runs on the real profile, so it exercises tool_choice auto; required is exercised by P1.6b on demo.

Done when (I run this myself):
make down && make up   -> exit 0
kubectl get pods       -> redis and agent Running next to vllm
make agent-check       -> answer contains 59; access-log lines for the run with x-step 1..n and x-expected-steps;
                          Redis shows status done and the run's messages; exit 0

versions.md (Python base image, Redis image), experiments/log.md (agent-check output)
