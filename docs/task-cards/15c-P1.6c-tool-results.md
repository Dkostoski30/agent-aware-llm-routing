# P1.6c: Tool results the demo model reads right

Goal:
The two misreadings that made P1.6b a no-go (required 6/10, auto 7/10) can no longer come from the tool results:
compare says which group is higher instead of returning a signed difference, and group_by's row count has a name
that cannot pass for a total. CSV tool results are rounded. Then make go-no-go reruns on the unchanged experiment.

Depends on:
P1.6b

Files allowed:
agent/agent_runtime/csv_tools.py, agent/agent_runtime/tools.py, agent/agent_runtime/loop.py,
agent/agent_runtime/config.py, agent/tests/ (test_csv_tools, test_agent_loop, test_app, test_agent_config),
config/real.yaml, config/sim.yaml, config/demo.yaml (agent.result_decimals),
experiments/go_no_go.py, experiments/tests/test_go_no_go.py (result file name), experiments/results/ (new result),
experiments/demo-go-no-go.yaml (compare's wrong_if_matches, decided during the work),
experiments/log.md, docs/task-cards/15c-P1.6c-tool-results.md

Interfaces / outputs:
- compare(file, by, value, agg, left, right) keeps its arguments. Its result no longer depends on which group is
  left: higher {group, <agg>}, lower {group, <agg>}, difference (higher minus lower, never negative), percent_more
  (difference as a percent of lower; null when lower is 0), and summary, one sentence that says the same, e.g.
  "North's sum of revenue (14351.1) is 3728.9 higher than South's (10622.2), 35.1% more." Equal groups: difference
  0, higher and lower in argument order, and the sentence says they are equal.
- The agg enum's count becomes row_count (the number of rows in a group, as csv_summary's row_count). The group_by
  and compare descriptions say it is not a total and that sum totals a column.
- New key agent.result_decimals (all profiles, with a comment): every number in a CSV tool's result, and in the
  summary sentence, is rounded to it. The calculator is not rounded: its result feeds the next operation.
- go_no_go.py names its result file <experiment>-<yaml hash>-<agent image tag>.csv; the image tag is the hash of
  the agent's build context (infra/deploy-agent.sh), so a result is tied to the agent code that produced it.

Notes:

new cases: the same result whichever group is left, equal groups, a lower value of 0, a negative lower value,
rounding in each tool and in the sentence, row_count's wording. The system prompt and
experiments/demo-go-no-go.yaml do not change, so the rerun compares run for run with P1.6b (fixed seeds).

## Decided before the work (2026-10-28)

- compare's result has the fields and the summary sentence: a 1.7B model copies text well, so the direction comes
  from Python, not from the model reading a sign.
- Result files carry the agent image tag, so P1.6b's result (demo-go-no-go-9440b109d5fa.csv, agent
  c61bb199c383) is not overwritten by the rerun.

## Decided during the work (2026-10-28)

- The first rerun crashed in the switch to auto with a connect timeout: the agent's Service rules on the node still
  led to the deleted pod more than 10 s after it was gone, the second failure of reaching the restarted agent through
  the Service (rule 8). go_no_go.py now sends the runs to the one Ready agent pod's IP; the served-mode check stays.
- The same run scored the copied compare sentence wrong: wrong_if_matches read the "35.1% more" after South's value
  as a claim about South. It now needs the comparative's "than" within two words, so the group before it is the one
  it is about. The question texts are unchanged, so the runs still compare with P1.6b's; the experiment file's hash
  changes with the regex.
