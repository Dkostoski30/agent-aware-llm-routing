# P3.8: Run tracker

Decided 2026-11-09 with the user: an active run counts `max(expected-steps − step, 1)` (a note goes on D2). `x-step` can pass `x-expected-steps` (P2.2b), and half of a task type's runs overrun its median (P2.4). A run still going has at least one more call coming, so the signal never reads zero under active runs.

Decided while planning: the module sits in `agent/agent_runtime/` as PLAN.md's layout has it, with only the standard library, so the replayer imports it through `PYTHONPATH=agent`. The metrics text is written by hand (`# TYPE` and one sample per gauge), since one or two gauges don't justify a new dependency (rule 5).
