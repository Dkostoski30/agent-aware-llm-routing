# P5.0: tooling for the squares

Added 2026-11-24, on branch `feature/phase-5`, after card 72 (P5.1a, P5.1a-2).

Goal:
P5.1's and P5.2's real comparisons are Williams squares of four files, a seed per file (Phase 5's decision 3). Before
they run: one command that runs a square's files and picks up a night that stopped, a comparison of N variants over
files of different seeds with its verdict fixed in code, and the numbers each file needs to be read on its own (what
system code it ran on, whether the replayer lagged, whether the load overloaded the pods).

Depends on:
Card 72 (`burst-fan-out-heavy`, P5.1a-2's late starts and overload rule).

Decided (the user, 2026-11-24; all Claude's recommendations):
1. **Seeds 6, 9, 10, 13.** P2.4's rule as a share: each of hotpotqa, gaia_dev, tau2 (three domains as one) and bfcl
   20-30% of the pattern's runs (4-6 of 20 on `steady-long`, where it gives P2.4's seed 6; 10-15 of 50 on
   `burst-fan-out-heavy`). 9, 10, 13 are the first three after 6 that meet it. Seed 6 misses it by one run (9
   gaia_dev of 50) and stays: it is the load P5.1a-2 checked.
2. **The verdict**, for each variant against the reference: in each file, gap = (reference's total run time - the
   variant's) / the reference's. **Faster** if the gap is over 0 in every file and its mean is more than its spread
   (max - min) over the files; **slower** the same with the signs turned; else **no difference shown**. No verdict
   when a kept run did not finish on either side.
3. **Overload per file:** each variant's calls waiting per pod after each burst go into its `.meta.json`, read from
   the same Prometheus as the stall check. Printed, not judged.
4. **Source in each `.meta.json`, and the comparison refuses files run on other system code.** Built as a hash of
   the system files on disk at the run's start rather than a git diff between commits (Claude, while building it): a
   commit check would refuse this card's own done-when, whose code was uncommitted when it ran, and the hash also
   catches uncommitted edits, which commits do not show.

Files:
- `loadgen/load_generator/experiment.py`: each `.meta.json` gets `source` (commit, uncommitted paths, and
  `system_sha256` over `SYSTEM_PATHS`: agent/, config/, gateway/, infra/, loadgen/, schemas/, sim/, Makefile,
  pyproject.toml, uv.lock) and `bursts_seconds`; each variant gets `late_starts` and `waiting` (its
  `<stem>-<variant>-waiting.csv` and each burst's most waiting per pod). The report prints both. `run_file` and
  `file_outputs` for the series.
- `loadgen/load_generator/waiting.py` (new): the waiting series and each burst's peaks.
- `loadgen/load_generator/compare.py`: `late_starts`, the calls whose gap ran over the trace's by more than
  `late_start_ms`.
- `loadgen/load_generator/plan.py`: `burst_starts`, the moments a burst of runs starts.
- `loadgen/load_generator/square_compare.py` (new): the comparison, `make square-compare SERIES=...`; writes
  `experiments/results/<series>-square.csv`. `experiment_compare.py` stays as it is: it pairs runs across files of
  one load, which a seed per file does not have.
- `loadgen/load_generator/series.py` (new): `make experiment-series NAME=...`.
- `config/report.yaml`: `burst_waiting_window_seconds: 60` (card 72's rule), `late_start_ms: 50` (every profile's
  `replay.gap_tolerance_ms`, which a test holds).
- `experiments/series/p5-0-sim-check.yaml`, `experiments/p5-0-sim-a.yaml` (seed 6: default, plugin),
  `experiments/p5-0-sim-b.yaml` (seed 9: plugin, default): the done-when's 2x2 square on sim. Its plugin has no
  priority, which the simulator does not have (P4.1).
- `Makefile`: the two targets.
- Tests: `test_waiting.py`, `test_series.py`, `test_square_compare.py` (new); `test_experiment.py`,
  `test_compare.py`, `test_replay_plan.py` (the seeds), `test_report_config.py` (its fixture gained the two new keys).
- This card, PLAN.md's P5.0 row, the `experiments/log.md` entry.

Done when:
`make test` and `make lint` pass, and the series of the two sim files runs from one command, then skips both when run
again.
