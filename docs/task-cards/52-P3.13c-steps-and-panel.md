# P3.13c: Steps under an answer, panel beside the chat

D14: the cluster panel sits beside the chat, and a toggle shows or hides it. P4.6's buttons will go at its bottom; this card leaves that space and adds nothing there.

Decided 2026-11-19 (user): one task, no split. The panel moves out of app.ts into the chats layout as its third column (chat list | chat | panel), so the login screens have none; the top bar's Cluster button, beside Chats, shows or hides it. Saved steps from GET /runs/{id} lack run_id and expected_steps, so run-view.ts gains savedStepCards on the fields they share. The expanded steps carry P2.6c's warning (a saved answer lost it in P3.13b), so it shows only after expanding. The answer whose run just ended opens expanded; older answers and every answer after a reload start collapsed. UI cohesion stays in Phase 6. The design system README's "the panel never collapses" gives way to D14.

Redis keeps a run's steps for `agent.history_ttl_seconds` (24 h), so older answers keep their text and lose their steps. The UI says so in one line instead of showing an error.
