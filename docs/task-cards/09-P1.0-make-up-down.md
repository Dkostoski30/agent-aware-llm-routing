# P1.0: make up / make down

Goal:
make down && make up brings both vLLM pods back to Ready from scripts alone, with no manual step.

Depends on:
Gate 0 (P0.7)

Files allowed:
Makefile (targets up, down), infra/download-model.sh (new), infra/down.sh (new),
infra/local/vllm-common.sh, infra/charts/vllm/values.yaml, infra/charts/vllm/templates/deployment.yaml (comments
that named make vllm-run as the model download), docs/task-cards/09-P1.0-make-up-down.md

Interfaces / outputs:
- make up [PROFILE=real|demo]: PROFILE defaults to real. Runs, in order: make vllm-stop (no Docker vLLM may hold
  the GPU), infra/install-k3s.sh, infra/download-model.sh PROFILE, make vllm-deploy PROFILE. Later Phase 1+ tasks
  add their component as one more step.
- infra/download-model.sh PROFILE: hf download of model.name at model.revision from config/<PROFILE>.yaml into
  ~/.cache/huggingface, the cache the vLLM pods mount. Replaces the manual make vllm-run before vllm-deploy.
- make down: infra/down.sh. Uninstalls the Helm releases make up installs, then stops k3s and every container
  (k3s-killall.sh). Keeps the k3s install, the vLLM image in k3s's containerd (~9 GB, re-pulling it crashed k3s in
  P0.7) and the HF cache (user decision). Later tasks add their release; app data will survive make down (D7).

Notes:
Both targets are idempotent: a second make down or make up changes nothing and exits 0.
No logic beyond shell orchestration, so no unit tests.

Done when (I run this myself):
make down            -> exit 0; systemctl is-active k3s -> inactive; nvidia-smi shows no vLLM process
make down            -> exit 0 again
make up              -> exit 0, ends with both vllm pods 1/1 Running
make service-check   -> answer + tool_calls through the Service, exit 0

Record in:
experiments/log.md (make up wall time)
