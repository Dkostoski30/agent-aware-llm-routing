# P1.6d: Calculator takes an arithmetic expression

Goal:
One calculator call evaluates a whole arithmetic expression, so "2x2x2", "1+1+1" and "7 times 8 plus 3" are one call
whose result is the answer. The 0.6B stops after the first of two dependent calls (2026-10-28: 2x2x2 -> 4,
1+1+1 -> 2; P1.3b: "7 times 8 plus 3" 0/10 with every prompt tried).

Depends on:
P1.6c

Files allowed:
agent/agent_runtime/tools.py, agent/tests/test_calculator.py, agent/tests/test_app.py, agent/tests/test_agent_loop.py,
agent/tests/test_csv_tools.py, config/real.yaml, config/sim.yaml, config/demo.yaml (the calculator clause of
system_prompt), docs/task-cards/15d-P1.6d-calculator-expression.md

Interfaces / outputs:
- calculator arguments: {"expression": "7*8+3"}. The schema's pattern allows digits, a decimal point, spaces,
  parentheses and + - * /, plus x and × for multiply and ÷ for divide, since the model copies them from the question.
- Result {"result": n}: exact arithmetic (fractions), every number read as written; a whole number as an exact int,
  any other value as the nearest float, so 123456789*987654321 keeps every digit and 0.1*3 is 0.3. Errors come back
  as {"error": ...}: division by
  zero, an expression that does not parse or uses anything but numbers and + - * /.
- Evaluated by walking Python's ast of the expression: only numbers, + - * / and unary minus/plus are accepted, never
  eval.
- system_prompt: "for any other arithmetic call the calculator tool once with the whole expression" replaces "use the
  calculator tool, one operation per call", the same text in every profile.
