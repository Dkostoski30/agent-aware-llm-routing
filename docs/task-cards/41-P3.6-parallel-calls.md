# P3.6: Parallel calls

Parallel calls come from the replayer's fan-out, not the demo agent (decided 2026-11-01). The parallel calls of one step reach the picker at almost the same moment, faster than a 50 ms metrics refresh can show them in the queue, so the plugin has to count its own calls in flight per group. Runs on sim (decided 2026-11-09).

```
# P3.6: Parallel calls

Goal:
Calls of one x-parallel-group stay on the run's pod while it has room, and spill to another pod only when it doesn't. A spilled
parallel call leaves the pin where it is.

Depends on:
P3.5

Files allowed:
gateway/runrouter/, config/real.yaml, config/real-plain.yaml, config/sim.yaml, config/demo.yaml (routing section, the burst
with fan-out pattern), infra/routing-values.sh, loadgen/tests/ (the pattern's tests only), experiments/log.md, PLAN.md (P3.6 row),
docs/task-cards/41-P3.6-parallel-calls.md

Interfaces / outputs:
- With routing.parallel_spill: room on the pinned pod = its waiting queue plus the group's calls already sent to it and not
  finished, at or under routing.parallel_queue_threshold. No room: the candidates without the pinned pod.
- The in-flight count per (run, group) rises in PreRequest and falls in ResponseBody at end of stream, whose hook also runs when a
  request is cancelled or fails (requestcontrol/plugins.go), so a failed call does not hold its count. A group with no pin yet
  (a fanned-out first step) binds at its first call.
- routing.parallel_queue_threshold, first guess 2 (a fan-out of 2, on a simulated pod running 2 at once).
- JSON log lines with reason parallel-stay and parallel-spill, with run-id, step, group, pod. The counter of P3.5 gains both.
- replay.patterns.burst-fan-out in every profile, the same in all (P2.3's comment promised it): burst's arrivals, fan_out share 0.5, k 2.

Notes:
Tests first, table-driven: the group stays while it has room; the k-th call spills once full; another group of the run counts
apart; a call's end frees room; a spilled call does not move the pin; flag off changes nothing. Upstream's RunningRequestsSize
is ignored here on purpose: it lags the same as the queue. "routing on" below means bash infra/set-routing.sh sim <a file with the
flags> first.
```
