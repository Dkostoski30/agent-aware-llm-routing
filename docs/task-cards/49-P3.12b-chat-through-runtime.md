# P3.12b: A chat message through every layer

The browser must not reach the agent runtime directly, since it has no login: the app backend checks that the run belongs to the user, then forwards. `make smoke` moves to this path, so from here on it also tests the app backend.

Decided while planning (2026-11-17): a message may carry run-request.v1's `seed`, sent with its run only and not saved, so `make smoke` keeps its seeded, repeatable answer through the chat path; the UI sends none. The events stream is read with an async httpx client with no read timeout (connect and write keep `app.runtime_timeout_seconds`): the runtime ends it when the run ends and a browser that leaves cancels it, so no new config key. The UI's `/api` proxy still goes to the agent until P3.13.
