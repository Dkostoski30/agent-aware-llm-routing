# P2.9: Validate the simulator against one real pod

Goal:
The same replay on one real vLLM pod and on one simulated pod gives results within ~10-15%, saved as a table. If not,
recalibrate (P2.8) once; a second miss is reported with the error, not hidden (PLAN.md section 4: "report the error
openly").

Depends on:
P2.7, P2.8

Files allowed:
experiments/validate-sim.yaml (new: trace, pattern, seed, metrics, tolerance), loadgen/ (comparison module, tests),
Makefile (only if make experiment can't run it), sim/ (validation table), experiments/log.md,
docs/task-cards/32-P2.9-sim-validation.md

Interfaces / outputs:
- make experiment NAME=validate-sim: the replay on the real profile at replicas 1, then on sim at replicas 1, same
  trace, pattern and seed; then sim/validation-<hash>.csv: per metric, real, sim, relative error.
- Metrics: TTFT p50/p95, call duration p50/p95, run completion time p50/p95, prefix-cache hit rate. Tolerance in the
  experiment file (0.15, the PLAN.md row's bound) with a comment.

Notes:
Tests first: relative error per metric from known traces, the pass/fail per metric against the tolerance. The
replay pattern must load the pod enough to queue (the simulator's job is behaviour under load), not only single
calls. Also run it at 2 pods if P2.8 found sharing the GPU changes per-pod timing, since D5 validates at 1<->2.

Record in:
experiments/log.md, sim/validation-<hash>.csv

## Decided (2026-11-06, before the plan)

- One `make experiment NAME=validate-sim`: each variant names its profile and replica count, and the vLLM release is
  swapped (`helm uninstall vllm`, `make vllm-deploy` or `make sim-deploy`, `infra/set-routing.sh`) when the profile
  changes, with no `make down`/`make up`, which asks for sudo mid-run. The sim variants run beside the real cluster's
  idle agent and Redis.
- Validate on the current `config/sim.yaml` first. On a miss, recalibrate once (delete
  `sim/calibration-5553d79b34d7-lora-1pod.csv` and its `.meta.json`, `make calibrate`, remap), note it in
  `experiments/validate-sim.yaml` so the rerun gets its own hash, and validate again; a second miss is reported.
- 1 pod and 2 pods, in pairs real then sim: real-1pod, sim-1pod, real-2pods, sim-2pods.
- Load: pattern `baseline`, seed 6, the converted trace `convert-apb-ca5fc26bbb1d-cd81f326aece.jsonl`.
- Proposed in the plan: only the 1-pod pair's misses trigger the recalibration; the 2-pod pair's are recorded as GPU
  sharing, which a recalibration cannot change.

## Built

- `loadgen/load_generator/validation.py`: the seven metrics per variant (nearest rank, warm-up runs left out), the
  relative error `|sim − real| / real`, `sim/validation-<hash>.csv`, the report lines; its `main` writes the table
  again from the experiment's CSV.
- `loadgen/load_generator/experiment.py`: per-variant `profile` and `replicas`, `check_same_replay` (pattern, shared
  prefixes, call deadline), deploy on a profile change, scale before the restart and back at the end, each variant's
  profile stamp in the meta, `finish` writing the table. Files with one `profile` run as before.
- Tests: `loadgen/tests/test_validation.py`, new tests in `loadgen/tests/test_experiment.py`; the fake cluster gained
  `deploy` and `scale`, recorded only, so the existing order assertions are unchanged.
