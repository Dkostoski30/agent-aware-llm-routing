Added 2026-11-20. PLAN.md's row P4.6: "Angular: demo buttons ("start 20 tasks", "kill pod")"; done when "Buttons trigger
the replayer and pod deletion". Split 2026-11-20 (the user): P4.6a the buttons (this card), P4.6b the "retry 1" tag that

Read before planning (Claude, 2026-11-20):
- The replayer has always run on the host: replay.py finds the gateway's, the pods' and the picker's ClusterIPs with
  kubectl (`_service_url`), and Prometheus scrapes its run tracker at the node's IP through a Service with no selector
  (infra/manifests/replayer-metrics.yaml, P3.8). The app backend runs in the cluster with no ServiceAccount rights.
- A replay writes each finished run's lines to `<out>.partial` as it goes (replay_to_file), and refuses an `out` that
  exists, so a second press needs a new file name, and the finished-run count can be read from the partial file.
- `make up` on real deploys 2 fixed pods (replicas 2) and no autoscaler; a killed pod is replaced by its ReplicaSet and
  loads for ~2-3 min. demo has one pod (card 60: a kill there leaves nothing to fail over to). sim has no app backend.
- The design (docs/design-system/components/DemoControls): Start with a steady/burst choice, disabled while a replay runs,
  the caption showing progress and the command it ran; Kill with a select of the pods that exist, the caption saying when
  one is gone. Pinned to the bottom of the cluster panel (card 52 left that space).

Decisions (asked 2026-11-20; the user chose the first option named in each):
1. Where the replay runs. A host runner: `make demo-runner`, a stdlib HTTP server in loadgen/, runs the same `make replay`
   and `kubectl delete`; the app backend reaches it as Prometheus reaches the replayer, a Service with no selector and an
   Endpoints object at the node's IP, with a shared token. (Offered: a Kubernetes Job from a replayer image, the app
   backend calling the API server; the replayer inside the app backend.)
2. How Kill deletes. Force, grace 0, as P4.4's checks: the calls on the pod fail and P4.4's retry sends them again
   elsewhere (PodFailureScreen). (Offered: a plain delete, which drains (P4.3); both buttons.)
3. Where the buttons show. Real only: `app.demo_controls.enabled` true in real, false in demo and sim. (Offered: real
   and demo.) Changed while building (Claude): real-plain is true too, since sim/tests/test_real_plain_profile.py holds
   it equal to real but for the adapter, and it is deployed only by P2.8's calibration.
4. The "retry 1" tag. Its own card, P4.6b. (Offered: in this card; dropped.)
